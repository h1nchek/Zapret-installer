# Zapret на Linux и его настройка

Это не официальная документация и не копипаста с реддита. Просто записал для себя, пока не забыл, как вообще заставить всё это работать. Может кому пригодится.

Вообще я не хотел писать именно публичный гайд для всех, но информации собралось уж слишком много, поэтому я сделал этот репозиторий публичным.

Речь про форк от Sergeydigl3 ([zapret-discord-youtube-linux](https://github.com/Sergeydigl3/zapret-discord-youtube-linux)). Он берёт за основу оригинальный zapret от bol-van и стратегии от Flowseal и оборачивает это в более-менее удобный скрипт для Linux. YouTube, Discord, всякое остальное такое «заблокированное».

Проверял на Arch Linux в 2025 году. На Ubuntu и Debian в целом то же самое, только пакеты ставятся через `apt`.

> 💡 Не хочется делать всё руками? В корне репозитория есть [автоустановщик](../README.md).

---

## Сначала: чего ждать

Не ждите, что скачаете, запустите и всё заработает за пять минут. У меня заняло часа полтора, из которых минут сорок я тупил на одной конкретной вещи (расскажу ниже). Блокировки у всех разные, стратегии подбираются методом тыка, и иногда то, что работало вчера, сегодня перестаёт: провайдеры не стоят на месте.

Ещё важный момент: скрипт работает только с **nftables**. Если у вас до сих пор крутится старый iptables и вы не знаете зачем, могут быть конфликты. Проверьте, что активно:

```bash
sudo nft list tables
```

Если пусто, всё чисто.

## Шаг 1. Зависимости

**Arch:**

```bash
sudo pacman -Syu --needed base-devel nftables git
```

**Ubuntu / Debian:**

```bash
sudo apt update && sudo apt install -y build-essential nftables git
```

Ничего особенного. Если nftables уже стоит, просто убедитесь, что он не конфликтует с `iptables-legacy`.

---

## Шаг 2. Клонирование и первый запуск

```bash
git clone https://github.com/Sergeydigl3/zapret-discord-youtube-linux.git
cd zapret-discord-youtube-linux
```

Дальше нужно скачать зависимости: это бинарник `nfqws` и набор стратегий из отдельного репозитория. Без этого шага сервис вообще не запустится, и вы получите непонятную ошибку (об этом ниже).

```bash
./service.sh download-deps --default
```

Флаг `--default` скачивает рекомендованные версии автоматически. Если хотите выбрать вручную, запустите без флага, скрипт покажет список. Рекомендованная версия `nfqws` на момент написания: v72.9.

После этого:

```bash
./service.sh
```

Появится интерактивное меню: запуск, управление сервисом, настройка конфигурации. Всё основное делается отсюда.

Если не хочется каждый раз вводить пароль, запустите один раз:

```bash
./service.sh setup-permissions
```

Это добавит `NOPASSWD` для `nft` и `nfqws`. Удобно, если планируете часто перезапускать.

## Шаг 3. Настройка: что реально менять

Основной файл конфигурации: `conf.env`. Лежит прямо в папке репозитория, никуда не устанавливается.

Редактировать можно двумя способами.

**Через скрипт** (проще, особенно если не хочется ломать руками):

```bash
./service.sh config show              # посмотреть текущее
./service.sh config edit              # интерактивно
./service.sh config set general.bat   # выставить стратегию напрямую
```

**Руками** через nano/vim, если знаете, что делаете:

```bash
nano conf.env
```

Самое важное, что там нужно проверить, это режим фильтрации. По умолчанию может быть включена фильтрация всего трафика, а это замедляет обычные сайты без всякой причины. Переключите на режим списка:

```env
MODE_FILTER=hostlist
```

И отредактируйте файл `list-general.txt`: туда вписываете домены, которые хотите пробивать. Не тащите туда списки на десять тысяч сайтов, которые кто-то выложил на гитхабе. Серьёзно. Запрос на каждый пакет будет сверяться со списком, и если там мусор, будет мусор в работе. Добавляйте только то, чем пользуетесь:

```text
example1.com
example2.org
```

Базовый домен покрывает все поддомены автоматически: `openai.com` сработает и для `chatgpt.com`, и для `oaistatic.com`.

## Шаг 4. Подбор стратегии

Это самая нервная часть. Запрет работает через модификацию пакетов на уровне ядра, и конкретный способ зависит от того, как именно ваш провайдер реализует блокировку. У кого-то работает первая же стратегия, у кого-то не работает ни одна из стандартных.

Для автоматического перебора есть скрипт:

```bash
sudo ./auto_tune_youtube.sh
```

Он прогоняет все доступные пресеты и записывает рабочий вариант в конфиг. Занимает несколько минут. Если после него YouTube всё равно не идёт, читайте раздел про браузер ниже.

## Шаг 5. Автозапуск

Через меню `./service.sh` выберите «Управление сервисом» → «Установить». Скрипт сам определит вашу init-систему.

Поддерживается: systemd, OpenRC, runit, dinit, s6. То есть работает не только на стандартных Ubuntu/Arch, но и на Gentoo, Void и других.

После установки сервиса команды для systemd:

```bash
sudo systemctl restart zapret_discord_youtube   # перезапуск
sudo systemctl status zapret_discord_youtube    # статус
```

Обратите внимание на подчёркивания. Имя сервиса: `zapret_discord_youtube`, через подчёркивание, не через дефис. Я потерял на этом минут сорок, потому что в старых гайдах везде написано через дефис, и bash тихо возвращает «unit not found» вместо нормальной ошибки. Проверить точное имя можно так:

```bash
systemctl list-units | grep zapret
```

Если хотите запускать без терминала, можно поставить ярлык в меню приложений:

```bash
./service.sh desktop install
```

Появится в категории «Сеть» или «Система» в зависимости от DE.

## Типичные проблемы

### «Ошибка: репозиторий со стратегиями не найден»

Самая частая. Возникает, если запустить `./service.sh`, не скачав зависимости. Лечится:

```bash
./service.sh download-deps --default
```

После этого перезапустить сервис.

### Сервис запустился, но YouTube всё равно не работает

Сначала проверьте браузер. Chrome и его форки по умолчанию используют QUIC (UDP-протокол), который zapret не всегда умеет обрабатывать правильно. Попробуйте отключить:

`chrome://flags/#enable-quic` → Disabled, перезапустить браузер.

Если после этого заработало, либо оставляйте так, либо поиграйтесь с UDP-фильтрацией в `conf.env`.

Ещё один флаг, который иногда помогает: Kyber (`chrome://flags/#use-kyber`). В некоторых регионах его отключение буквально мгновенно решает проблему с торможением видео. Логики особой нет, просто попробуйте.

### Пинг в играх вырос, лагает Discord-звонок

Zapret по умолчанию может перехватывать UDP-трафик на игровых портах. Откройте `conf.env`, найдите настройки UDP-портов и либо закомментируйте строку целиком, либо уберите порты, которые конфликтуют. TCP для браузера при этом продолжит работать.

### Всё перестало работать после обновления

Такое бывает: провайдеры меняют методы блокировки, старые стратегии перестают работать. Обновите репозиторий и заново скачайте зависимости:

```bash
git pull
./service.sh download-deps --default
sudo systemctl restart zapret_discord_youtube
```

Если и это не помогает, загляните в Issues и Discussions репозитория. Скорее всего там уже обсуждают.

## Вместо итога

Штука работает, но требует чуть больше возни, чем хотелось бы. Зато это не VPN, не сторонний сервис, которому надо доверять трафик, и не платная подписка. Всё крутится локально, трафик идёт напрямую. После настройки про него можно забыть: сервис висит в автозапуске и не напоминает о себе.

Если что-то не работает после часа попыток, почти наверняка это уже обсуждалось в дискуссиях репозитория. Там довольно активное сообщество.
